Clinical AI System

Clinical Agent Skills

A doctor's guide to teaching your AI clinical reasoning, protocols, and institutional knowledge.

What It Is

Clinical Skills are structured instruction files that teach your AI assistant how to think, reason, and act within specific medical domains — cardiology, emergency medicine, your hospital's sepsis protocol, or how you prefer discharge summaries formatted.

They are not prompts you type each time. They are permanent clinical knowledge loaded automatically when relevant.

Think of it like training a medical resident: you write the "rotation manual" once (the skill file), and the resident applies that knowledge to every patient they see in that department without you repeating instructions.

Three Types of Clinical Skills

Type Purpose Example
Core Reasoning Universal clinical thinking patterns — safety checks, output formats, humility rules How to structure a differential, when to flag "Can't Miss" diagnoses, how to express uncertainty
Domain Expertise Specialty-specific medical knowledge and reasoning frameworks Cardiology ACS protocols, nephrology electrolyte emergency thresholds, oncology staging workflows
Workflow Playbooks Task-specific step-by-step procedures for common clinical actions Medication reconciliation process, discharge summary structure, pre-operative clearance checklist

How the System Remembers

Your AI does not dump the entire patient chart into its working memory. It uses a layered compression system — similar to how you, as a clinician, hold different levels of detail in mind: raw lab values for today's patient, a summary of last week's admission, and institutional protocols you have memorized.

Level Form Compression Clinical Example
L0: Raw Traces Full encounter notes, lab JSON, tool outputs 1:1 Original FHIR bundles from the EHR
L1: Episodic Memory Structured encounter summaries 5–20× "Patient presented with chest pain; troponin negative; discharged with GERD precautions"
L2: Procedural Skills Reusable clinical pathways 50–500× "Chest pain rule-out protocol: ECG within 10 min → troponin ×2 → risk stratify"
L3: Declarative Rules Institutional policies 1,000×+ "All ACS protocols require cardiology consult before discharge"
Why This Matters

Most AI systems fixate on L1 (storing raw notes). Your skill system actively promotes knowledge up the chain — turning repeated encounters into reusable protocols, and protocols into hard institutional rules. This keeps the AI's working memory lean while preserving deep expertise.

How It Works

When you open a patient chart, the system automatically assembles the right skills for that clinical moment. It does not load all medical knowledge at once — only what is relevant to the current patient and task.

Example: A 55-year-old diabetic presents with chest pain.

The system detects cardiac symptoms → loads the Core Reasoning skill (safety first) + the Cardiology domain skill (ACS protocols) + the Differential Diagnosis workflow (structured reasoning). It does not load nephrology dosing tables or pediatric growth charts.

Precision Loading

A nephrology skill never interferes with a cardiology case. Your hospital's sepsis protocol only activates when sepsis is suspected. This is precision medicine applied to AI reasoning.

What a Skill Looks Like

Below is the actual template for the Core Clinical Reasoning skill — the foundation every other skill builds upon. This is not pseudocode. This is the real text the AI reads before evaluating your patient.

SKILL.md — Clinical Reasoning Agent

Identity

You are a clinical decision support assistant embedded in an EHR environment. You do NOT replace physician judgment. You augment it by organizing information, suggesting evidence-based considerations, and catching potential oversights.

Communication style:

  • Concise and actionable (surgeons read during procedures; internists read between rooms)
  • Structured with clear headings
  • Humble about uncertainty: always distinguish "suggested" from "confirmed"
  • Never alarmist: present risks proportionally

Clinical Reasoning Framework

For every patient interaction, follow this sequence:

  1. Data Verification — Check for missing critical data. Flag stale labs (>48h acute, >3mo chronic). Note data conflicts.
  2. Problem List Synthesis — Maintain active problem list: [Active | Improving | Resolved | Chronic]. Link to evidence.
  3. Differential Reasoning — Probabilistic approach. Pre-test probability + evidence + required rule-out. Always include "Can't Miss." Stop at 5 unless asked for more.
  4. Action Recommendation — Prioritize by urgency (Time-Critical / Same-day / Routine). Tie rationale to patient context.
  5. Safety Check — Cross-reference allergies. Check renal/hepatic dosing. Verify no duplicate therapy.

Interaction Patterns

When receiving new patient data:

  • Summarize clinical picture in 3–5 sentences first
  • Identify top 2–3 clinical questions this data raises
  • Suggest what additional data would change management

When asked for a differential:

  • Lead with most likely diagnosis and reasoning
  • Include "Can't Miss" section with specific rule-out criteria
  • End with suggested next diagnostic step

When reviewing medications:

  • Check against allergies, renal function, hepatic function, pregnancy status
  • Highlight therapeutic duplications
  • Suggest deprescribing opportunities for elderly/polypharmacy patients

Standard Output Format

## Clinical Snapshot
[2-3 sentence summary of current state]

## Key Considerations
- [Point 1 with evidence]
- [Point 2 with evidence]

## Suggested Actions
1. **[Priority]** Action — Rationale
2. **[Priority]** Action — Rationale

## Safety Flags
- [Any alerts requiring immediate attention]
- [Data gaps limiting safe recommendation]

## Evidence Note
[Guideline name + year, or explicit uncertainty statement]

Hard Constraints

NEVER:

  • Suggest discontinuing life-sustaining therapy without explicit attending confirmation
  • Provide definitive cancer staging or prognosis without pathology/radiology correlation
  • Recommend off-label uses without noting off-label status
  • Generate prescriptions for controlled substances
  • Make clinical decisions based solely on patient-reported history

ALWAYS:

  • Include units for lab values (e.g., "K+ 5.2 mEq/L")
  • Specify institutional protocol vs. general guideline
  • Ask for clarification when the clinical question is ambiguous
  • Acknowledge when data is insufficient for a safe recommendation

This core skill is loaded for every patient interaction. Domain skills (cardiology, nephrology) and workflow skills (medication reconciliation) layer on top of it — they never replace these safety foundations.

Where Skills Live

Skills are organized in a folder tree. The system scans this structure automatically and loads skills based on the patient's clinical context.

/skills/
core/
clinical-reasoning.md # Universal: safety, humility, evidence
domain/
cardiology.md
nephrology.md
emergency-medicine.md # Specialty-specific reasoning
workflow/
differential-diagnosis.md
medication-reconciliation.md
discharge-summaries.md # Task-specific playbooks
institutional/
your-hospital-policies.md # Local protocols, formulary
Folder Logic

core/ is always loaded. domain/ loads based on patient problems. workflow/ loads based on what task you are performing. institutional/ loads based on your hospital ID. This keeps each interaction focused.

How to Add a New Skill

You do not need to write code. You write clinical logic in a simple text file with a specific structure. The system reads it automatically.

Step-by-Step

1

Create the Skill File

Navigate to the /skills/ directory. Create a new folder for your skill (e.g., cardiology) and add a file named SKILL.md.

The file must start with a metadata block (called "frontmatter") that tells the system when to use this skill.

SKILL.md — Cardiology Example 
---
name: cardiology
description: |
  Cardiovascular disease management including ACS, heart failure,
  arrhythmia, and preventive cardiology. Activates when patient has
  active cardiac conditions, chest pain, or user requests cardiology.
tags: [cardiology, cardiovascular, chest-pain, heart-failure]
requires: [core/clinical-reasoning]
---

## Activation Triggers
Load this skill when:
- Patient problem list contains: CAD, HF, AF, HTN-emergency
- Chief complaint: chest pain, dyspnea, palpitations, syncope
- User explicitly asks cardiac question

## Specialized Reasoning Patterns

### Chest Pain Evaluation
1. Immediate risk stratification: HEART score (ED) or pre-test probability
2. ECG priority: Must be <4h for acute symptoms
3. Troponin interpretation: Trend > absolute value; delta 3-6h
4. Can't Miss: Aortic dissection, PE, esophageal rupture

## Output Format
Use structured cardiac summary:
- Cardiac Assessment (2-3 sentences)
- Risk Stratification (HEART/Grace/HAS-BLED)
- Key Findings
- Recommendations (prioritized)
- Follow-up
2

Add Supporting Files (Optional)

For deep reference material that should not clutter the main skill, create additional files in the same folder. The AI can request these on demand.

/skills/domains/cardiology/
SKILL.md ← Main skill file
acs-protocol.md ← Supporting reference
echo-interpretation.md ← Supporting reference
3

Restart or Refresh the System

The system scans the /skills/ directory automatically on startup. If you add a file while the system is running, use the refresh command or restart the service to load the new skill into the catalog.

The skill now appears in the system catalog and will be loaded automatically when its activation triggers are met.

How to Import Existing Skills

If your institution has a shared skill library, or you want to use skills developed by other departments, you import them by placing the files in the correct directory structure.

Method 1: Direct File Copy

Copy the .md skill files into your /skills/ directory maintaining the folder structure. The system will auto-discover them on next scan.

Import via File System 
# From a shared network drive or Git repository
cp -r /shared/skills/cardiology /skills/domains/
cp -r /shared/skills/sepsis-protocol /skills/workflows/

# Restart to load
systemctl restart clinical-agent

Method 2: Git-Based Import (Recommended for Teams)

For institutions with multiple contributors, store skills in a Git repository. This provides version control, audit trails, and peer review.

Import from Git Repository 
# Clone the institutional skill library
git clone https://git.hospital.org/clinical-skills.git /skills/

# Or add as a submodule to your main system
git submodule add https://git.hospital.org/clinical-skills.git skills/

# Pull updates when protocols change
cd /skills && git pull origin main
Version Control Best Practice

Every skill file should include a guideline_version and last_updated date in its frontmatter. The system checks these and warns if a skill references outdated guidelines (e.g., a 2023 ACS protocol when 2025 guidelines exist).

Method 3: API Import

If your system exposes a management API, you can POST skill content directly:

Import via API 
POST /api/v1/skills
Content-Type: application/json

{
  "name": "cardiology",
  "content": "---\ndescription: Cardiology domain...\n---\n## Activation...",
  "tags": ["cardiology", "chest-pain"],
  "requires": ["core/clinical-reasoning"]
}

How to Modify a Skill

Clinical knowledge evolves. Protocols update. Your institution adopts new guidelines. Modifying a skill is editing a text file — no deployment or coding required.

Editing Workflow

1

Locate the Skill

Find the SKILL.md file in your /skills/ directory. Use the skill name from the catalog if you are unsure of the path.

2

Edit with Any Text Editor

Open the file in VS Code, Vim, or any text editor. The file uses Markdown syntax with a YAML frontmatter block at the top.

What you can safely change:

  • Reasoning steps and clinical logic
  • Output formats and templates
  • Activation triggers and conditions
  • References to guidelines or protocols

What requires care:

  • The name field — changing it breaks dependencies from other skills
  • The requires field — removing a dependency may remove safety checks
3

Update the Version Metadata

Always update the last_updated date and increment the guideline_version if you changed clinical content. This ensures the system tracks which recommendations came from which skill version.

Before and After Modification 
# BEFORE (original skill)
---
name: cardiology
description: Cardiovascular disease management
guideline_version: "ACC/AHA 2023"
last_updated: "2024-01-15"
---

### Heart Failure GDMT
Ensure ACEi/ARB + Beta-blocker + MRA

---

# AFTER (modified skill)
---
name: cardiology
description: Cardiovascular disease management
guideline_version: "ACC/AHA 2025"  ← Updated
last_updated: "2026-04-20"          ← Updated
---

### Heart Failure GDMT
Ensure ARNI (preferred) or ACEi/ARB + Beta-blocker + MRA + SGLT2-i  ← Updated per 2025 guidelines
4

Test Before Deploying

Use the built-in skill test framework to verify your changes do not break clinical reasoning. Create a test scenario file in the skill's folder:

Test Scenario File 
# /skills/domains/cardiology/tests/chest-pain-scenarios.yaml

- name: "Atypical chest pain in diabetic female"
  input: "55F diabetic with 2h of epigastric burning, no SOB"
  expected_contains: 
    - "atypical presentation"
    - "ACS cannot be excluded"
    - "ECG"
  forbidden_contains:
    - "GERD diagnosis"  # Should not conclude GERD without workup
    - "discharge home"   # Should not discharge without rule-out

- name: "STEMI with contraindication to fibrinolysis"
  input: "65M chest pain 2h, ST elevation V1-V4, BP 88/52"
  expected_contains:
    - "cardiogenic shock"
    - "primary PCI"
    - "contraindicated to fibrinolysis"
5

Commit and Deploy

If using Git, commit with a descriptive message and push. The system will load the updated skill on next restart or via hot-reload if supported.

Git Workflow 
git add skills/domains/cardiology/
git commit -m "Update cardiology skill to ACC/AHA 2025 guidelines

- Add SGLT2-i to GDMT for HFrEF
- Update ACS protocol with high-sensitivity troponin thresholds
- Add HAS-BLED assessment for AF anticoagulation"
git push origin main
