# 3. API ENDPOINTS
############################################################

Router prefix is "/protocol_master" (underscore), but every individual
route path below uses a dash ("/protocol-master/..."). Full effective
paths therefore look like:
  /protocol_master/protocol-master/bulk
  /protocol_master/protocol-master/list
  /protocol_master/protocol-master/select
  ...etc.
This underscore-prefix + dash-route mismatch is almost certainly
unintentional and worth flagging/confirming against how the frontend
actually calls it.

### PROTOCOL CRUD  (5 endpoints)
------------------------------------------------------------
  POST   /protocol-master/bulk
         function : add_protocols
         does     : Bulk upsert a list of ProtocolMaster docs. Upserts by
                    protocol_id; returns counts of newly added vs. updated
         touches  : protocol_master_collection

  POST   /protocol-master
         function : add_protocol
         does     : Insert a single new protocol. Returns 409 Conflict if
                    a protocol with the same protocol_id already exists
         touches  : protocol_master_collection

  PUT    /protocol-master/{protocol_id}
         function : update_protocol
         does     : Update an existing protocol (used by the "Edit
                    Protocol" form). Returns 404 if not found. Forces
                    protocol_id in the saved payload to match the URL
                    param even if the request body disagrees (guards
                    against a mismatched/edited body from a disabled
                    client-side field)
         touches  : protocol_master_collection

  DELETE /protocol-master/{protocol_id}
         function : delete_protocol
         does     : Delete a single protocol by protocol_id. Returns 404
                    if nothing was deleted
         touches  : protocol_master_collection

  DELETE /protocol-master
         function : delete_all_protocols
         does     : Delete ALL protocols with no confirmation step.
                    Returns count deleted
         touches  : protocol_master_collection
         note     : no auth/role check visible in this file guarding this
                    destructive endpoint - worth double-checking upstream
                    middleware actually restricts it

### PROTOCOL BROWSING / MATCHING  (3 endpoints)
------------------------------------------------------------
  GET    /protocol-master/list
         function : list_protocols
         does     : Lists protocols for the browser UI. Optional `search`
                    does a case-insensitive regex match across
                    protocol_name, aliases, disease_sites. Optional
                    `patient_id` triggers diagnosis-based matching
                    (via _get_patient_match_context +
                    _match_protocols_by_diagnosis) to flag up to 5
                    protocols as "recommended": true and sort them first.
                    Strips full drug_schedule from the list response
                    (only drug_names) to keep payload light
         touches  : protocol_master_collection, summary_collection (read
                    only, only when patient_id is supplied)

  GET    /protocol-master/{protocol_id}
         function : get_protocol
         does     : Fetch a single full protocol document by protocol_id.
                    Returns 404 if not found
         touches  : protocol_master_collection

  POST   /protocol-master/select
         function : select_protocol
         does     : Core "pick a protocol for a patient" flow. Requires
                    patientId and protocolId (400 if missing). Looks up
                    the raw protocol, builds clinical context from the
                    patient's summary doc, calls the Groq LLM to adapt the
                    fixed protocol to that patient (dosing notes, start
                    date, safety flags, etc. - NOT drug list or doses,
                    which are locked), then upserts the merged regimen
                    into chemotherapy_records_collection keyed on
                    (patient_id, doctor_id). Returns the raw protocol, the
                    clinical context sent to the LLM, the raw LLM JSON,
                    and the final merged/adapted regimen in one response
         touches  : protocol_master_collection, summary_collection (read
                    only), chemotherapy_records_collection

# 4. SUPPORTING HELPER FUNCTIONS (not routes, 6 functions)
############################################################
------------------------------------------------------------
  _strip_markdown(text)
         Strips asterisk runs (bold/italic markdown) from a string and
         trims whitespace. Used to clean diagnosis text pulled from
         patient_summary before using it for matching/display.

  _get_patient_diagnosis(patient_id)
         Reads patient_summary, tries summary.diagnosis_header first, then
         falls back to the first entry in summary.confirmed_diagnoses
         (handles both plain-string and dict-shaped entries). Returns ""
         and logs a warning if nothing usable is found. NOTE: this
         function is defined but not called anywhere else in this file -
         appears to be superseded by _get_patient_match_context (dead
         code, or reserved for future use).

  _get_patient_match_context(patient_id)
         Broader version of the above - builds a wider text pool
         (diagnosis_header + all confirmed_diagnoses + first 2000 chars of
         full_text/paragraphs) specifically because histology-only
         diagnosis headers often omit the anatomical site. Feeds
         _match_protocols_by_diagnosis.

  _match_protocols_by_diagnosis(match_text, limit=5)
         Tokenizes match_text into keywords (>4 chars, minus a hardcoded
         medical stopword list), builds a regex OR-pattern, pulls up to 50
         candidate protocols matching on disease_sites/aliases/
         histology/protocol_name/display_name, then ranks candidates by a
         simple keyword-hit-count score across those same fields and
         returns the top `limit`. Powers the "recommended" flag in
         GET /protocol-master/list.

  _build_clinical_context(summary_doc)
         Extracts a structured context dict from a raw patient_summary
         doc for LLM adaptation: diagnosis, first 6000 chars of full
         clinical narrative, plus ECOG score, serum creatinine, hemoglobin,
         and an allergy flag - each pulled by scanning the summary's
         timeline entities for name-fragment matches (e.g. "ecog",
         "creatinine", "hemoglobin"/"haemoglobin", "allergy"/"allergic")
         and regex-extracting the first number from the matched evidence
         text.

  _adapt_protocol_with_llm(proto, context)
         Sends the fixed protocol (as ground truth, explicitly instructed
         NOT to be altered) plus the patient's clinical context to Groq
         (model "llama-3.3-70b-versatile", JSON-forced response,
         temperature=0). Expects back treatmentIntent, startDate,
         doseAdjustments, concurrentTherapy, reasonForChange, safetyFlags.
         Raises HTTP 500 on any Groq API failure. Then merges the LLM
         output with the untouched protocol fields (drug schedule, cycle
         count/interval, premedications, hydration, supportive care, lab
         requirements, references, etc.) into a single `merged` dict
         shaped for the frontend's regimen form, and returns both the raw
         LLM JSON and the merged object.
